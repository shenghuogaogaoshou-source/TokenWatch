# TokenWatch 优化清单

> 基于 2026-11-11 这一版代码的实际状态整理。每条都写清「现在什么样 / 为什么值得改 /
> 大概怎么做」，成本用 S（半天内）/ M（1–2 天）/ L（要做设计取舍）标。
> 优先级只看一件事：**改完之后，界面上的数字是不是更可信**。

---

## P0 · 数据可信

### 1. 「只给金额」的平台在 KPI 里没有痕迹（M）
Kimi 这类平台只返回金额、不返回 token，勾了关注模型后整笔计入。
现在过滤条会写「N 家无模型明细 · 整笔计入」，但 KPI 上看到的是一个大数，
用户很难意识到「这里面有一块根本没被筛选过」。

**做法**：KPI 副标题按来源拆开——「官网实扣 ¥8.76（已按模型筛选）+ ¥2.18（无模型明细，整笔计入）」。
数据已经能算出来（`fxSummary()` 的 `noStr`）。

### 2. 半年 / 全年依赖官网窗口（M）
DeepSeek 给 180 天、Kimi 给 30 天、智谱票据一失效就什么都没有。现在加了本地存档兜底，
但存档只有「应用开机时采过的那几天」，且只存按日合计。

**做法**：把存档做成「首启回填」——启动时按 365 天拉一次，之后每天增量；
`usage_filtered` 在官网缺天时用存档补那一天（现在只在整家缺数据时补）。
注意口径：同一天两边都有时要定谁优先，建议「官网 > 存档」并记 `source`。

### 3. ~~票据到期没有预警~~（已完成）
已做：`expiry.level` 为 `urgent`（≤2 天）或 `expired` 时发系统通知，同一家一天一次。
注意：通知是前端发的，**应用没开着就不会响** —— 真要做到「关机也提醒」得常驻托盘（见 17）。

## P1 · 体验

### 4. ~~账户体检：一次点完所有账户~~（已完成）
已做：账户页「全部测一遍」，串行跑（并发打三家会撞 DeepSeek 的 429），
结果写回各自卡片，末尾汇总。遗留：结果**下次刷新就没了**，见 16。

### 5. ~~余额还能撑几天~~（已完成）
已做：余额下方「按近 7 天日均 ¥0.23 算，还能撑 99+ 天」，低于 3 天转警示色。
遗留：日均固定除以 7，账户只用了 3 天时会低估续航，见 18。

### 6. 明细表不能排序、不能下钻（M）
一行一家，想看「哪天花得最多」「哪个模型最贵」只能去官网。

**做法**：表头点一下按该列排序；点行展开该家的逐日 + 逐模型小表
（`/api/platform` 已经带 `model_days`，数据都在手上）。

### 7. 模型页筛选维度太少（M）
466 个模型只有「厂商 / 搜索 / 只看已选 / 只看已接入」四个维度。

**做法**：加「价格区间」「上下文 ≥ N」「免费模型」三个开关。目录里 `cny` 和
`context` 都有，纯前端过滤。

### 8. 换机迁移：账户配置一键导出/导入（S）
凭据在 `platform_creds.json`、账户在 `usage.db`，换台机器就得重新接一遍。

**做法**：导出 `{accounts, models, creds}` 的加密包（口令派生密钥），导入时逐条 upsert。
**必须做确认**：明文导出等于把登录态写在文件里，默认给加密选项。

## P2 · 能力边界

### 9. 火山方舟升「仅余额」（M，缺凭据没法验证）
官方有 `QueryBalanceAcct`（billing 服务，V4 签名，AK/SK），可以做，但**我这里没有
真实 AK/SK，写完也验证不了**，所以宁可不写——写一个跑不通的接口比不写更糟。

**做法**：等有凭据时，按 V4 签名（HMAC-SHA256 + `X-Date` + `X-Content-Sha256`）
实现 `fetch_ark_balance`，能力档从 `catalog` 升到 `balance_only`。

### 10. 同模型跨平台价差（暂不做）
现在目录里每个模型只归一个平台，实际比不出任何一组。
等接了中转站（New API 会给 `/v1/models` 的价）再做才有意义，那时按
「末段同名」分组比价。这也是为什么这一版改成「按你的实际用量折算」——
那个用现有数据就能算出结论。

### 11. 中转站类型识别（S）
New API / One API / Veloera 的额度接口路径和字段都不一样，现在按 New API 的
`/api/user/self` 试，失败了就只说失败。

**做法**：探测 `/api/status` 的 `version` 字段识别类型，按类型选接口；
识别不出来再退回通用 `/v1/dashboard/billing/*`。

### 12. 一键换来源（L，且有风险）
真要「换来源」得改 CC Switch 的 provider 或 Claude Code 的 `base_url`，
等于替用户改配置，改错了他自己都不知道。

**做法**：只做「复制切换命令」，不直接写；或者在设置里加一个显式的
「允许修改本机配置」开关，默认关。

## 工程

### 13. `app.js` 已经 2100 行（M）
渲染、合并、过滤、导出、通知全挤在一个文件里，改一处要读一千行。

**做法**：按页拆 `overview.js / chart.js / table.js / pricing.js`，用 `window.XXX` 暴露入口
（models/accounts/picker 已经是这个结构，照着来）。

### 14. 测试脚本不在仓库里（S）
`shots/_audit.js` 这套巡检很值钱，但 `shots/` 被 gitignore 了，换台机器就丢。

**做法**：移到 `tests/e2e/`，`npm test` 起 mock 服务 + 跑巡检；CI 只跑 mock 版。

### 15. 日志不轮转（S）
`tokenwatch.log` 只追加，跑一年就是几十 MB。

**做法**：`logging.handlers.RotatingFileHandler(maxBytes=2MB, backupCount=3)`。

### 16. 版本号与「有新版本」提示（S）
现在没有版本号，用户不知道手里的 exe 是哪一版。

**做法**：页脚显示 `git describe` 或写死的 `VERSION`；启动时比对 GitHub 最新 release
（可选，会联网，默认关）。

## 2026-11-11 第二轮：新发现

### 16. 测试结果刷新即消失（S）
「全部测一遍」把结果写在卡片 DOM 上，下一次 `renderProviders()` 重建卡片就没了。
用户测完想对照着去改凭据，一刷新就看不见了。

**做法**：结果存 `state.lastTest[id] = {at, status, detail}`，渲染卡片时带上（超过 10 分钟标灰）。

### 17. 提醒只在页面开着时有效（M）
余额/票据通知都是前端 `new Notification()`，关掉窗口就什么都不会发生。
而「余额快没了」「票据明天过期」恰恰是关了窗口才需要提醒的事。

**做法**：桌面端加托盘常驻（pystray 或 Win32 `Shell_NotifyIcon`），
由后台线程每 10 分钟跑一次采集并按阈值提醒；窗口关了进程仍在，退出走托盘菜单。

### 18. 续航的日均算法会在新账户上失真（S）
固定除以 7 天。账户只用了 2 天、花了 ¥40，会算成「日均 ¥5.7」，
实际日均是 ¥20 —— 续航被高估 3 倍多。

**做法**：分母取 `min(7, 有数据的天数)`，并在文案里写清用的是几天。

### 19. 智谱卡片三条红框叠在一起（S）
「余额查询失败」「登录票据已失效」「凭据失效，请重新获取」说的是同一件事，
视觉上像三个不同的故障。

**做法**：一家只留一条主因横幅（取最具体的那个），其余降级成行内小字；
横幅里直接给「重新获取」按钮，点开就是登录窗口（`/api/grab_cred` 已就绪）。

### 20. 导出只有「当前区间」（S）
归档表里已经有逐日数据，但 CSV 只能导当前区间，想拿全量去 Excel 里做分析做不到。

**做法**：导出菜单给两个选项：「当前区间明细」和「全部历史逐日（含模型）」。
后者直接从 `daily_usage` 出，别走渲染层。

### 21. 隐藏页也在重绘（M）
`renderAll()` 每次把四页全画一遍，其中三页根本看不见。数据量上来后
（466 个模型行的过滤、趋势图 SVG）会明显卡一下。

**做法**：按 `state.page` 只重绘当前页 + 标记脏页，切页时再补画。
参考 `shell.js` 的 `goPage()`，那里已经在管页面切换了。

### 22. 前端没有任何缓存失效策略（M）
`/api/catalog?full=1` 466 条、`/api/data` 逐日明细，每次刷新都全量重拉并重绘。
服务端有 60s 缓存，前端没有。

**做法**：给 `getJSON` 加 `If-None-Match`/ETag 或简单的「5 分钟内复用上次结果」，
只在 `force` 时打网络。
